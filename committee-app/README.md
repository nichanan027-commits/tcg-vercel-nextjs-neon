# TCG Smart Claim Pitching (ระบบเสนอคณะกรรมการจ่ายค่าประกันชดเชย)

แอป Next.js + Neon Postgres สำหรับงานเสนอจ่ายค่าประกันชดเชยต่อคณะกรรมการ ตั้งแต่ชีตข้อมูลจนถึงร่างรายงานการประชุม

```
ชีต "Bank Approved" ──นำเข้า──▶ รอบประชุม (ตามคอลัมน์ Appointment)
                                   │
        ┌──────────────────────────┼───────────────────────────┐
        ▼                          ▼                           ▼
   ภาพรวม/แดชบอร์ด            โหมดนำเสนอ (สไลด์)          รายงานเสนอ (พิมพ์/PDF)
   แก้หมายเหตุเงื่อนไขการจ่าย    บันทึกมติรายตัวในที่ประชุม
        └──────────────────────────┬───────────────────────────┘
                                   ▼
                      ร่างรายงานการประชุม + มติ (จากมติที่บันทึก)
```

## ที่ระบบทำ

| หน้า | ทำอะไร |
|---|---|
| `/` | รายการรอบประชุม สรุปจำนวน/ยอดเงิน/มติ และนำเข้าชีต (ลิงก์ Google Sheets หรือวาง/อัปโหลด CSV) |
| `/meetings/[id]` | แดชบอร์ดรอบนั้น กรองตามสถาบันการเงิน แก้ **หมายเหตุเงื่อนไขการจ่าย** (ค่าธรรมเนียม / คืนชุดคำขอ / Bank Statement) และมติรายตัว ดูประเด็น + เอกสารหลักฐาน |
| `/meetings/[id]/present` | สไลด์ที่ประชุม: ปก, ภาพรวมรายธนาคาร, ตารางรายธนาคาร (อนุมัติทั้งหน้าได้), สไลด์ต่อหนึ่งรายที่มีประเด็นพร้อมเอกสารและปุ่มมติ, สรุปขอมติ ใช้ลูกศร/Space/Home/End และ F เพื่อเต็มจอ |
| `/meetings/[id]/report` | รายงานเสนอตามรูปแบบตารางวาระพิจารณาจ่าย (ลำดับ / ชื่อโครงการ / ประเภท / วงเงิน / ขออนุมัติจ่าย / หมายเหตุ) พิมพ์หรือบันทึก PDF |
| `/meetings/[id]/minutes` | **ร่าง**รายงานการประชุม: หัวเรื่อง วันที่ ตารางวาระ ข้อความมติ (ช่วงลำดับ, ยอดรวมเฉพาะที่อนุมัติ) รายที่เลื่อน/ไม่อนุมัติ และประโยคอ้างแนวปฏิบัติสำหรับรายที่มีประเด็น |

กติกาจากชีต: หัวคอลัมน์เทียบด้วยคำขึ้นต้น (ไม่สนช่องว่าง/ขึ้นบรรทัดใหม่) ต้องมี `Bank` หรือ `ธนาคาร`, `โครงการ`, `รอจ่าย`
- มีข้อความใน `ประเด็นพิจารณา` → รายมีประเด็น (🔴)
- เงื่อนไขมีคำว่า "ฟ้อง" หรือ "คดี" → ดำเนินคดี (🟡) *(ปรับเกณฑ์ได้ที่ `caseFlag` ใน `src/lib/sheet.ts`)*
- รายไม่มี `Appointment` จะอยู่ในรอบ "ไม่ระบุรอบ"
- นำเข้าซ้ำได้: อัปเดตข้อมูลจากชีต **คงมติและหมายเหตุที่แก้ในระบบ** ไว้ แถวที่หายจากชีตจะถูกซ่อน (ไม่ลบ) และกลับมาเองเมื่อมีในชีตอีก
- คีย์ของแต่ละรายคือ `เลขที่ L/C + ฉบับที่` ต่อรอบ (ถ้าไม่มี L/C ใช้เลขแถว) เลขลำดับในรายงานคือลำดับแถวในชีต ถ้าแทรก/ลบแถวหลังบันทึกมติ เลขลำดับจะเลื่อนตาม

## ติดตั้ง

### 1) Neon
สร้างโปรเจกต์ที่ [neon.tech](https://neon.tech) แล้วคัดลอก connection string (แบบ pooled) ตารางสร้างให้อัตโนมัติเมื่อเรียกใช้ครั้งแรก

### 2) Vercel
- Import รีโปนี้ แล้วตั้ง **Root Directory = `committee-app`** (รีโปนี้มี `index.html` ของ Route2Own อยู่ที่ราก ไม่ถูกแตะ)
- ตั้ง Environment Variables ตาม `.env.example`:

| ตัวแปร | ความหมาย |
|---|---|
| `DATABASE_URL` | connection string ของ Neon |
| `APP_PASSWORD` | รหัสผ่านเข้าระบบ |
| `SESSION_SECRET` | สตริงสุ่มยาวอย่างน้อย 32 ตัวอักษร (`openssl rand -base64 32`) |

ถ้าไม่ตั้ง `APP_PASSWORD` ระบบ production จะปฏิเสธทุกคำขอ (503) เพราะข้อมูลมีชื่อบุคคลธรรมดา

### 3) รันในเครื่อง
```bash
cd committee-app
npm install
cp .env.example .env.local      # ไม่ใส่ DATABASE_URL ก็ได้ จะใช้ฐานข้อมูลในเครื่อง (PGlite) ที่ .data/pglite
npm run dev
```
ทดสอบ: `npm test` (ตรรกะชีต/รายงาน/ฐานข้อมูลบน PGlite), `npm run typecheck`

## ความปลอดภัยและข้อจำกัด
- ใช้รหัสผ่านร่วมหนึ่งชุด (คุกกี้เซสชัน HMAC, httpOnly, 12 ชั่วโมง) ยังไม่มีบัญชีรายบุคคลหรือบันทึกว่าใครกดมติ
- API ยอมรับเฉพาะ JSON; นำเข้าจากลิงก์ได้เฉพาะ `docs.google.com/spreadsheets` (ระบบสร้างลิงก์ export เอง) ชีตต้องแชร์เป็น "ทุกคนที่มีลิงก์ (ผู้ดู)" ถ้าไม่ได้ ให้ดาวน์โหลดเป็น CSV แล้ววางแทน
- ไฟล์หลักฐานคือลิงก์ Google Drive ในคอลัมน์ `ลิงก์หลักฐาน` แสดงตัวอย่างในกรอบได้เมื่อไฟล์แชร์เป็น "ทุกคนที่มีลิงก์ (ผู้ดู)" ถ้าตั้งสิทธิ์จำกัด ผู้เปิดต้องล็อกอิน Google ด้วยบัญชีที่มีสิทธิ์ (มีลิงก์ "เปิดในแท็บใหม่" สำรองไว้)
- ข้อความจากชีตแสดงผ่าน React (escape อัตโนมัติ) และลิงก์เอกสารรับเฉพาะ `http(s)`
- ร่างรายงานการประชุมเป็นร่างจากมติที่บันทึก ต้องตรวจแก้ถ้อยคำก่อนใช้จริง
- `npm audit` ยังเตือน PostCSS ที่ฝังมากับ Next.js (ช่องโหว่อยู่ที่การ stringify/อ่าน source map ของ CSS ตอน build ซึ่งระบบนี้ใช้เฉพาะ CSS ของตัวเอง) แก้ได้เมื่อ Next.js ออกรุ่นที่อัปเดต PostCSS

เวอร์ชัน Google Apps Script ของแดชบอร์ดเดิมอยู่ที่ `../apps-script/` ใช้ได้โดยไม่ต้องมีฐานข้อมูล แต่ไม่มีการบันทึกมติ
